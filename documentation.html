5.2 Next.js Routing Explained

The application uses the Next.js App Router (app/ directory), which marks a shift from the previous Vite SPA structure.

Concept How strictly it works
File-system Routing Folders inside app/ define routes. A folder named dashboard creates a /dashboard route.
page.tsx The unique UI for a route. app/dashboard/page.tsx renders the UI for /dashboard.
layout.tsx Shared UI for a segment and its children (e.g., headers, sidebars). Preserves state on navigation.
route.ts Creates an API endpoint. app/api/auth/route.ts becomes accessible at /api/auth.

6.4 Database Setup & Management

The project uses PostgreSQL managed by Supabase.

Environment Variables

Create a .env file in the root directory with the following keys:

POSTGRES_URL="postgres://user:password@host:port/postgres"
SUPABASE_URL="https://your-project.supabase.co"
SUPABASE_ANON_KEY="your-anon-key"
SUPABASE_SERVICE_ROLE_KEY="your-service-role-key" (for admin)

Running Migrations

Database schemas are defined in database/schema.sql. To apply changes:

  1. Ensure your .env file is configured with the correct POSTGRES_URL.
  2. Run the migration script: 
    npm run migrate
  3. The script will connect to the database and apply the SQL schema.

When a caller dials your Twilio phone number, or when the application dials out to a user, the voice agent uses Google Gemini to hold natural, real-time conversations. This guide walks you step-by-step through setting up, deploying, and optimizing your Twilio integration.

Voice Agent Architecture & Request Flow

20.1 Creating a Twilio Account & Finding Credentials

To power voice calls, you must first create a Twilio account and acquire your API keys. Follow these steps:

  1. Sign Up / Log In: Go to the Twilio Official Website and create a free developer account, or sign in to your existing dashboard.
  2. Open the Twilio Console: Navigate to your main console dashboard.
  3. Locate Account Info: On your console homepage, find the Account Info pane. Copy the following credentials:
    • Account SID: A long identifier starting with AC (e.g., ACc0df277036ea...).
    • Auth Token: Click Show to reveal and copy your secret authorization token.
  4. Buy an Active Phone Number:
    • In the left-hand navigation sidebar, click Develop > Phone Numbers > Manage > Active Numbers.
    • Click Buy a number (or search for trial numbers if you're on a free trial).
    • Make sure the phone number supports Voice capabilities.
    • Purchase the number and copy it down exactly (e.g., +12182827359).

20.2 Configuring Environment Variables

Open your local project configuration or your Vercel Environment Variables dashboard and add your credentials under the exact variable names utilized by the server:

# ─── Twilio Integration Credentials ───
TWILIO_ACCOUNT_SID="ACXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
TWILIO_AUTH_TOKEN="your_twilio_auth_token_here"
TWILIO_PHONE_NUMBER="+12182827359"

Note: Remove any extra spaces or enclosing quotes when configuring these keys on Vercel to ensure clean string loading.

20.3 Setting Up Inbound Call Webhooks

For the AI Agent to answer the phone when someone dials your Twilio number, you must connect the Twilio phone line to your application's Next.js API endpoints:

  1. Go to the Twilio Console > Active Numbers and select your phone number.
  2. Scroll down to the Voice & Fax settings section.
  3. Find the A Call Comes In option:
    • Set the first dropdown option to Webhook.
    • In the URL field, paste your production app deployment URL followed by the voice webhook endpoint: 
      https://your-domain.vercel.app/api/twilio/voice
    • Set the next dropdown to HTTP POST.
  4. Configure the call logs and duration tracking:
    • In the Primary Handler Fails or Status Callback URL section, enter the status callback endpoint: 
      https://your-domain.vercel.app/api/twilio/status
    • Set the method to HTTP POST.
  5. Click Save at the bottom of the page to commit the changes.

CRITICAL STEP: Disabling Vercel Deployment Protection

By default, new Vercel deployments enable Deployment Protection (Vercel Authentication). This places an interactive login wall in front of every preview and production URL, blocking automated traffic.

Why This Breaks Twilio Webhooks:

Twilio's servers are external automation machines. They lack your login credentials and browser cookies. When a call occurs and Twilio tries to request the webhook at /api/twilio/voice, Vercel redirects Twilio to a login portal (HTTP 302/401). Because Twilio receives an HTML login page instead of the expected TwiML XML response, the call fails instantly with Twilio Error 11200 - HTTP Retrieval Failure.

How to Disable Vercel Authentication:
  1. Open your Vercel Dashboard and select your AI Suite project.
  2. Go to the Settings tab in the top navigation menu.
  3. In the left-hand column, click Deployment Protection.
  4. Find the Vercel Authentication block.
  5. Toggle the switch or select the dropdown option to set it to Disabled (turn off authentication completely for Production and Preview branches).
  6. Click Save to apply.

Note: The application codebase includes an automation bypass function (appendVercelBypassParams) that will append bypass keys if configured. However, to guarantee 100% webhook reliability and prevent call drops in production, completely Disabling Vercel Authentication in Vercel Settings is the absolute, industry-recommended solution.

22. Flutterwave Payment Gateway Integration Guide

The Flutterwave Payment Gateway is a world-class payment platform that enables merchants to accept payments in local currencies across Africa (including NGN, GHS, KES, UGX, ZAR) and internationally in USD, EUR, and GBP. It supports credit/debit cards, direct bank transfers, mobile money, and regional web wallets.

This beginner-friendly guide walks you step-by-step through setting up Flutterwave in the AI Suite platform, from creating an account to testing transactions and checking API routes.

21.1 Creating a Flutterwave Account & Finding Credentials

To start accepting payments, you must create a Flutterwave merchant profile. If you do not want to use real money yet, Flutterwave provides a sandbox dashboard where you can simulate successful card payments and transfers:

  1. Register an Account: Go to the Flutterwave Sign Up Page and create your business or individual profile.
  2. Access the Dashboard: Once logged in, you will be taken to your Merchant Dashboard.
  3. Switch to Test Mode: In the bottom left corner of the dashboard sidebar, toggle the switch to "Test Mode". This ensures that you can test payment flows without spending or charging actual money.
  4. Locate API Keys:
    • In the left sidebar menu of the Flutterwave Dashboard, go to Settings > API Keys.
    • Copy the following three keys exactly:
      • Public Key: Starts with FLWPUBK_TEST- (e.g., FLWPUBK_TEST-a123b456...) and is safe to expose in front-end code.
      • Secret Key: Starts with FLWSECK_TEST- (e.g., FLWSECK_TEST-z987y654...). Never share this key! Keep it secure as it authorizes transactions.
      • Encryption Key: A unique, shorter cryptographic string (e.g., 55a29f8d...) used for card transaction payloads.

21.2 Configuring the Admin Dashboard Settings

Unlike other platforms that require editing text configuration files on your server, AI Suite lets you activate payment gateways dynamically through your browser. Follow these steps to configure your system settings:

  1. Log In as Administrator: Go to your platform's /login page, authenticate with an administrator account, and navigate to the Admin Dashboard.
  2. Open System Settings: Click on System Settings in the left admin sidebar (or visit /admin/settings directly).
  3. Navigate to Payments: Select the Payment tab in the Settings Panel.
  4. Fill Out General Currency Options:
    • Platform Currency: Select your preferred billing currency (e.g., USD, NGN, GHS) from the dropdown list.
    • Enable Payments: Toggle this switch to ON (Enabled).
  5. Select and Configure Flutterwave:
    • In the Payment Gateway dropdown list, select Flutterwave.
    • A new Flutterwave Configuration panel will open below.
    • Paste your copied Public Key into the corresponding field.
    • Paste your Secret Key into the Secret Key field.
    • Paste your Encryption Key (Optional) into the Encryption Key field.
  6. Verify the Connection:
    • Click the Test Connection button in the Flutterwave card.
    • This triggers an API test call to your server. Your server makes a live transaction request to Flutterwave's endpoints.
    • If valid, a green success banner saying "Flutterwave connection verified successfully!" will display in the bottom-right corner.
  7. Save Your Settings: Click the Save Changes button in the top right header to write your active credentials into the database.

Secure Database Storage Architecture

In AI Suite, payment credentials are not hardcoded in the local .env file. To keep settings secure and configurable dynamically in production, all keys are saved securely in the system_settings table inside your PostgreSQL database. The database schema in [schema.sql](file:///*/ai-suite/database/schema.sql#L116-L138) provides native columns for flutterwave_public_key, flutterwave_secret_key, and flutterwave_encryption_key. The data is retrieved on the server via db.getSettings() inside [db.ts](file:///*/ai-suite/src/lib/db.ts#L432-L477) and saved via db.saveSettings().

21.3 Configuring Automated Webhooks

Webhooks are crucial server-to-server notifications sent by Flutterwave. They ensure that users are credited with their purchased tokens even if they accidentally close their browser tab, lose connection, or close their phone immediately after submitting a payment.

  1. Open Webhooks Dashboard: In your Flutterwave merchant dashboard, go to Settings > Webhooks.
  2. Enter Webhook Details:
    • URL: Enter your live website's production URL followed by the Flutterwave webhook path: 
      https://your-domain.vercel.app/api/webhook/flutterwave
    • Secret Hash: Create a unique random string (e.g., flw_hash_secret_129847) to secure the webhook. Note that the AI Suite server verifies all transactions authoritatively by making direct calls to Flutterwave’s verification endpoints using the secure key for absolute safety.
    • Webhook Events: Ensure the charge.completed checkbox is active.
  3. Save Webhook: Click Save to confirm.

CRITICAL STEP: Vercel Webhook Deployment Protection

If you deploy your site to Vercel, make sure that Deployment Protection (Authentication) is turned off for your production and preview environments.

If Vercel Authentication is active, any automated callback requests sent by Flutterwave's servers to /api/webhook/flutterwave will be rejected with an HTTP 401 Unauthorized redirect to a login portal. This stops token delivery. Go to your Vercel Dashboard > Settings > Deployment Protection and set Vercel Authentication to Disabled to guarantee webhook delivery.

21.4 Technical Architecture & Developer File Map

For developers who wish to explore or modify the code behind the Flutterwave implementation, the following codebase file mapping highlights how requests are processed:

  • Gateway Class: [flutterwave.ts](file:///*/ai-suite/src/lib/gateways/flutterwave.ts)

    Contains the core SDK logic. Utilizes Axios to communicate with Flutterwave's standard REST API. Implements checkout generation and transaction verification.

  • Gateway Routing Factory: [gateway-factory.ts](file:///*/ai-suite/src/lib/gateways/gateway-factory.ts)

    Bridges active configurations with system drivers. Dynamically switches to FlutterwaveGateway when Settings designate paymentGateway: 'flutterwave'.

  • Checkout API Route: [checkout/route.ts](file:///*/ai-suite/app/api/checkout/route.ts)

    Handles POST requests when subscribers click pricing plan cards. Initiates hosted checkout payments and passes metadata (userId, userEmail, planId) to Flutterwave.

  • Callback Verification API Route: [verify/route.ts](file:///*/ai-suite/app/api/checkout/verify/route.ts)

    Executes when user is redirected back to the app page. Pulls Flutterwave's transaction_id, triggers verification API, increments token balance, and saves payment/subscription rows.

  • Webhook Endpoint Route: [webhook/flutterwave/route.ts](file:///*/ai-suite/app/api/webhook/flutterwave/route.ts)

    Receives POST signals when transactions conclude. Verifies payments securely in the background, offering a second layer of insurance to ensure users get credited.

  • Admin Settings UI Layout: [AdminSettings.tsx](file:///*/ai-suite/src/views/admin/AdminSettings.tsx)

    Renders the admin settings panels and triggers key checks via `/api/admin/test-flutterwave` to verify client secret validity.

21.5 Troubleshooting Integration Issues

If you encounter any issues during your setup or testing, review these standard problems and solutions:

Problem / Error Root Cause Step-by-Step Solution
"Connection Failed" when clicking Test Connection Your Secret Key is incorrect, has trailing spaces, or belongs to another account environment. Ensure you copied the entire key starting with FLWSECK_TEST-. Remove any whitespace. Ensure "Test Mode" is on.
User gets redirected to checkout, but sees "Invalid Currency" The platform currency set in Settings (e.g. USD) is not supported by your merchant account or target country. Check your merchant account settings or select your home currency (like NGN) in the Admin Payment tab.

2. Inspect server logs for database insertion failures.
3. Verify that metadata was sent by checkouts.
"Flutterwave Secret Key is not configured" in console Keys were not saved properly or payment gateway is misconfigured. Go to Admin Settings > Payment, re-paste the Secret Key, click Save Changes, and refresh.

  2. Access the Dashboard: Once your account is set up, log in to your dashboard.
  3. Verify Mode: In the upper menu of your Paystack dashboard, make sure the toggle is set to Test Mode for development. Once your account is activated and ready for production, you can switch to Live Mode.
  4. Navigate to Settings: On the left-hand sidebar, scroll down and click on Settings.
  5. Open API Keys & Webhooks: Click on the API Keys & Webhooks tab at the top of the Settings page.
  6. Locate API Secret Key:
    • Under the API Keys section, you will find your API Keys configured for your current mode.
    • Copy the Test Secret Key (starts with sk_test_) or your Live Secret Key (starts with sk_live_).
    • Note: Click the eye icon next to the key to make it visible. You may be asked to enter your password for security.

23.2 Configuring the Admin Dashboard Settings

Once you have your Paystack Secret Key, you can enable Paystack dynamically inside the AI Suite Admin panel without touching any configuration files:

  1. Log In as Admin: Log into your platform with an admin account, and head over to the Admin Dashboard (/admin).
  2. Open Settings: Click on System Settings in the left admin sidebar, and choose the Payment tab.
  3. Select Platform Currency: Set your platform's base billing currency (e.g. NGN, GHS, KES, or USD).
  4. Set Gateway to Paystack: In the Payment Gateway dropdown list, select Paystack.
  5. Paste Secret Key: In the new Paystack Configuration panel, paste the copied Secret Key.
  6. Test and Verify: Click the Test Connection button. The application will connect directly to the Paystack API. If successful, you will see a green success message.
  7. Save Settings: Click Save Changes at the top of the page. This writes the settings directly to the database.

Secure Database Storage Architecture

In AI Suite, payment gateway credentials are not stored in raw text files. They are saved in the system_settings database table. The database schema in [schema.sql](file:///*/ai-suite/database/schema.sql#L77-L78) includes native columns for paystack_secret_key and paystack_currency. The server retrieves these values dynamically using the db helpers in [db.ts](file:///*/ai-suite/src/lib/db.ts).

23.3 Configuring Automated Webhooks

Webhooks allow Paystack to notify your server asynchronously when a payment succeeds. This guarantees that user accounts are credited with their purchased tokens even if they close their browser tab before the redirection completes:

  1. Retrieve Webhook URL: Your system's webhook listener is located at: 
    https://your-domain.vercel.app/api/webhook/paystack
  2. Configure in Paystack: In your Paystack Dashboard under Settings > API Keys & Webhooks, locate the Webhook URL field.
  3. Enter Webhook URL: Paste your Webhook URL into the field.
  4. Save Changes: Click the Save button to activate webhook delivery.
  5. Add Webhook Secret to Env: For webhook signature verification, copy your Webhook secret or the API key itself if used as verification, and set it as PAYSTACK_WEBHOOK_SECRET in your .env file: 
    PAYSTACK_WEBHOOK_SECRET="your_paystack_webhook_secret_or_key_here"

CRITICAL STEP: Vercel Webhook Deployment Protection

If you deploy your app to Vercel, make sure that Deployment Protection (Authentication) is disabled for your target environment.

If Vercel Authentication is active, external webhook requests from Paystack's servers to /api/webhook/paystack will fail with an HTTP 401 Unauthorized redirect. To avoid this, go to your Vercel Dashboard > Settings > Deployment Protection and set Vercel Authentication to Disabled.

23.4 Technical Architecture & Developer File Map

For developers modifying the code behind the Paystack payment gateway, here is the file mapping for the implementation:

  • Gateway Class: [paystack.ts](file:///*/ai-suite/src/lib/gateways/paystack.ts)

    Handles the API requests to Paystack endpoints for creating transaction sessions and verifying reference IDs.

  • Gateway Factory: [gateway-factory.ts](file:///*/ai-suite/src/lib/gateways/gateway-factory.ts)

    Dynamically instantiates and returns the PaystackGateway driver when the setting paymentGateway equals 'paystack'.

  • Checkout API Route: [checkout/route.ts](file:///*/ai-suite/app/api/checkout/route.ts)

    Initiates a payment session with Paystack and returns the checkout URL to redirect the user.

  • Verify API Route: [verify/route.ts](file:///*/ai-suite/app/api/checkout/verify/route.ts)

    Fires on user redirection back to the platform to check the payment reference, confirm success, and grant tokens to the database.

  • Webhook Endpoint Route: [webhook/paystack/route.ts](file:///*/ai-suite/app/api/webhook/paystack/route.ts)

    Asynchronously handles Paystack verification callback POSTs for robust fulfillment.
